# TsaoDFT README Visual Design System

This design system was generated with the workflow used by UI/UX Pro Max: product classification, pattern selection, style/color/typography synthesis, anti-pattern filtering, and a pre-delivery accessibility check.

## Product and pattern

- Product type: scientific developer tool / research infrastructure / documentation-led SaaS.
- Pattern: hero-centric identity + evidence-first bento grid + compact scientific diagrams.
- Style: Swiss Modernism 2.0, Minimalism, Accessible & Ethical, restrained Data-Dense UI.
- Design dials: variance 4/10, motion 1/10 (static SVG), density 6/10.

## Tokens

- Background: `#F6F8FC`
- Surface: `#FFFFFF`
- Primary ink: `#0B1220`
- Secondary text: `#526175`
- Primary blue: `#2563EB`
- Cyan: `#0891B2`
- Success: `#16A34A`
- Warning: `#D97706`
- Error: `#DC2626`
- Border: `#D9E2EE`
- Display/body: Inter-compatible system sans stack
- Technical labels: JetBrains Mono-compatible system monospace stack
- Spacing: 8 / 12 / 16 / 24 / 32 / 48 px
- Radius: 8 / 14 / 16 / 24 px

## Visual rules

1. One dominant message per figure.
2. Text remains readable at GitHub README width; no body text below 10 px.
3. Color is never the only status signal; labels accompany every status.
4. One AI-assisted conceptual cover only; all other figures remain deterministic synthetic demos.
5. Every scientific-looking figure includes source/status/units or an explicit non-data notice.
6. No emoji icons, decorative neon, AI purple-pink gradients, mixed visual metaphors, or feature-card walls.
7. The same palette, border, radius, grid and typography tokens are used across all assets.

## Pre-delivery checklist

- [x] Contrast-oriented light surface system
- [x] SVG role, title and accessible description
- [x] Visible AI/non-data disclosure
- [x] Stable dimensions required by repository validators
- [x] No external font or image dependency
- [x] No unsupported quantitative or engine-execution claim
- [x] Bilingual README uses the same asset set
